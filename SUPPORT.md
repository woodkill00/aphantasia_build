# Getting help

For using Imagery Field, start with the [user guide](imagery-app/README.md), [examples](examples/README.md) and [troubleshooting](docs/troubleshooting.md). The [compatibility record](docs/compatibility.md) distinguishes tested behavior from unverified devices and workflows.

## Ordinary questions, bugs and ideas

Open a [GitHub issue](https://github.com/woodkill00/aphantasia_build/issues/new/choose). The issue forms help collect a reproducible report. For a usage question, use **Usage question** in the issue chooser. There is no support email, service-level agreement or guaranteed response time. This is an engineering preview, not a medical support service.

Useful reports include:

- App version and source/runtime hash if known; where you obtained the HTML.
- Device/OS and exact browser version; how you opened the file.
- Clear steps, expected behavior and actual behavior.
- Viewport/zoom/reduced-motion settings when relevant.
- A minimal **synthetic** reproduction or reviewed screenshot, if useful.

**Public issues and attachments are public.** Do not share real observation notes, health information, identities, credentials, tokens, private URLs or unreviewed logs. Scene/sequence names can contain personal text too. Recreate the problem with neutral names and generated/example content instead of uploading a real export. Inspect screenshots for tabs, notifications, filenames and machine paths before attaching them.

Do not post exploit details in a public issue. For security findings, use the verified private reporting route in [SECURITY.md](SECURITY.md).

## What support can and cannot establish

A bug report can improve app behavior or documentation; it cannot establish medical suitability, imagery improvement, sensory safety or clinical efficacy. Do not increase brightness, contrast or viewing duration to chase an effect. Stop using the visual display if it causes symptoms; the [viewing guidance](imagery-app/README.md#before-viewing) is not a diagnostic service.

Compatibility reports are welcome even when a platform is currently unverified. Label what was actually tested, rather than interpreting a passing automated or emulated test as full device support.
