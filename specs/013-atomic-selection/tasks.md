## Precise acceptance cases

All cases below are future requirements, not recorded results. Use synthetic scenes only and preserve exact-source commands, versions, runtime hashes and failures.

### Pure and adversarial model

1. Selection reducers cover empty/one/twelve, layer-order canonicalization, newest-added primary, primary removal fallback, Select all retaining primary, explicit primary changes and all hostile IDs/options/accessors. Deep inputs remain unchanged.
2. Every movement/align/distribute/reorder/delete command rejects a mixed locked/unlocked selection with no partial result, even when a locked endpoint would not move. Duplicate locked sources is allowed; originals remain defensive-record-identical.
3. Common translation of 12 items preserves all pairwise offsets exactly in integer-hundredth lattice space, not raw floating subtraction. At each inset edge choose one common pointer delta from the complete zero-plus-nonzero feasible set; exact multi-nudge rejects as a whole. Cover all five ratios, legacy wide/tall geometry, all families, rotations, contours/outlines/shadows and floating-point inward endpoints. Bounds tests must include authored circle/dot records that return `geometry.kind === "polygon"`, alongside legacy radius-based records.
4. Snap a primary at 41.23 with a second member offset 7.11: the primary lands on the allowed 1/5/10 grid and the second retains 711 hundredths of lattice offset. Switch primary and obtain the defined different anchor result. No feasible grid intersection rejects, rather than silently unsnapping or collapsing spacing.
5. Six alignments change only intended item-axes, target the original union for newly computed mutations and meet their 0.005/0.01 plus EPS postconditions; an already-satisfied no-op uses only its 0.01+EPS spread predicate. Both branches preserve IDs/nonselected records/order. Run the triangle-rotation drift fixture and repeated commands for every edge/center mode; after the first success, 100 repeats leave exact coordinates, history and redo unchanged. Rotated asymmetric shapes demonstrate body-bound center versus stored-center distinction. Initial edge spread 0.009 is preserved unchanged, while 0.011 must enter the compute/validate branch. Invalid final envelope rejects without per-item clamp.
6. Variable-width equal-gap fixture produces 15/50/85 centers for widths 10/20/10 in span 10–90; equal-center output fails. Test reversed draw order, exact leading-edge ties, nested shapes, negative gap, zero gap, hundredth rounding that would produce overlap, endpoint/error tolerances and all ratios. Run the explicit tolerated-endpoint repeat fixture plus rotated cases that round an endpoint, for both axes, and require 100 exact no-op repeats with unchanged endpoint/interior bytes, history and redo. Test gap-spread values just below/above 0.02+EPS and negative-gap values just inside/outside the comparison allowance; no tolerance may relax canonical insets or bias quantization.
7. Singleton center retains its existing X/Y=50 helper behavior; multi center uses one rounded common delta per changed axis, preserves lattice offsets, and reaches union midpoint within 0.005+EPS of 50, never stacks items. Already-satisfied/zero/subquantum axes retain exact raw payloads. Test X/Y/both and 100 repeats with no drift/history growth; invalid centering rejects wholly.
8. Stable layer algorithm covers contiguous/interleaved selections, top/bottom no-op and crossing an unselected locked item; selected/nonselected subsequence order is preserved.
9. Duplicate counts 6+6 succeed and 7+7 reject atomically. New IDs respect six-digit schema and reserve current/history/planned identities. Delete all yields a valid static empty scene but invalid sequence capture. Undo/redo restores exact IDs and ordering. Clear/evict old history, recycle a now-free text ID within the same generation, and prove captured old-revision input cannot target its new record.
10. Forty mixed transactions fit, the forty-first evicts oldest, undo+redo total stays 40, no-op preserves redo and branching clears it only on success. Later selection-only change does not break undo; lock conflict consumes no entry. Reorder undo respects newly locked targeted records.

### DOM, state and integration

Bad raw input or invalid/locked candidate leaves them unchanged except documented concealment/rollback/invalidation; raw text is not erased by field refresh. Assert canonical positions roll back to the exact pre-gesture bytes; the fresh invalid text, invalid marker and pending-input indication remain; no provisional coordinate is reintroduced by replaying stale DOM fields; selection/history follow rejection policy; and late pointerup cannot commit. Exercise both singleton and multi-selection integration paths and multiple invalid fields; use enabled global fields for the multi-selection raw-input case, not a supposedly user-editable disabled inspector. Separately inject failure before completed-command controller stage and after successful final publication during raster/UI refresh: the former preserves canonical state/stacks, the latter leaves one complete hidden committed edit and one matching history transition, with an honest failure status. ## Evidence recording rules

Record each executed procedure as PASS, FAIL, BLOCKED or NOT RUN with exact source/tree/runtime hash and bytes, commands, runtime/browser versions, counts, timings, synthetic fixtures and actual inspected captures. Preserve earlier failed attempts. Do not report the acceptance list itself as a completed test. Native emulation, physical devices, actual zoom, cross-engine, OS file handling, assistive technology and qualified sensory/research review are separate evidence classes.

A changed source repair requires affected regression reruns and the final aggregate gates. Keep the security boundary and all assertions. A slow or failed gate is not permission to weaken tests, remove validation, install packages, retry indefinitely, deploy or publish. The only proposed budget change is the independently review-required, coverage-driven Feature 013 estimate in specification §12; current Feature 012 CI is unchanged. The integration owner updates IF-050, not a new feature-specific progress board.
