# Requirements quality and acceptance checklist

Feature 013. This is a review checklist, not a completion register. [The queue](../../../project-queue.json) owns status/evidence; [tasks](../tasks.md) are the fixed acceptance map. A checked design requirement is not an executed implementation test.

## Specification quality

- Is the feature strictly session-only atomic multi-selection, with groups reserved for separate Feature 014 and no selection overlay?
- Are the accepted contract digest, frozen Feature 012 tree/local equivalent, still-required verified-main dependency and lack of current Feature 013 acceptance explicit?
- Is `{ids, primaryId}` closed, stable-ID-based and draw-ordered, with every reducer/primary fallback defined?
- Do checklist, neutral Select only, Move anchor, timeline membership and singleton inspector controls have unambiguous and distinct meanings?
- Are raw authored edits preserved independently of provisional DOM repaint, from ordinary input events through cancellation/rejection/Hide?
- Are planning, provisional staging, final publication and post-publication render failure distinguished without partial state/history outcomes?
- Does each command specify whether viewport is required, with valid data commands still available without a canvas?
- Are full-record locks, selected-target reorder protection, duplicate exception and current-lock history preflight explicit before no-op/consumption?
- Are exact accepted payload preservation, changed-axis writes, lattice invariants, singleton compatibility and independently feasible exact zero specified?
- Are snapping, half-step rounding, no-grid rejection and no per-item clamping covered without normalization or inset relaxation?
- Are shared returned-kind body/outline bounds, shadow exclusion and authored/legacy aspect semantics clear?
- Are alignment, centering and distribution comparison-only predicates, new-result postconditions, EPS and 100-repeat no-drift requirements explicit?
- Does distribution mean equal edge gaps with original outer span, exact tie order and precision-overlap rejection, not equal centers?
- Are 12-item preflight, bounded temporary ID reservations, stable one-layer algorithm and deletion fallback specified?
- Is history one 40-total stream with exact documents/selections and concrete target checks, independent of current selection equality?
- Are every successful/failed replacement, sequence-only import, accepted history, generation/revision and Feature 012 provenance boundary covered?
- Are source/model/DOM/native/visual/performance/physical/AT/research evidence classes kept separate, with no release/storage/network/timing expansion?

## Pure model and precision review

- Closed records reject unknown fields, accessors, wrong prototypes, duplicate/missing IDs and nonfinite/malformed values without mutation.
- Selection cardinalities zero/one/twelve and every primary transition produce canonical draw order; commands enforce minimum counts and handler policy.
- All mixed-lock mutation rejects are atomic, including unchanged endpoints and locked no-op requests; duplicate sources remain exact and copies unlocked.
- Near-hundredth payload, outlined-dot inward boundary, opposite-bound zero-only and mirrored Y fixtures pass exact byte/lattice assertions.
- Zero/subquantum/no-op/rejection/unchanged axes preserve payload/history/redo; real moves change only permitted axes and Undo restores original residues.
- Primary grid filtering preserves lattice offsets and existing rounding; impossible snap rejects instead of unsnapping or deforming the set.
- Returned polygon dot/circle, rotated asymmetric shape, contour/outline and shadow-exclusion bounds use shared geometry; derived overflow/underflow rejects.
- Six alignments, X/Y/both centering and horizontal/vertical equal gaps meet branch-specific tolerances and preserve exact first results for 100 repeats.
- Unequal widths, leading-edge ties, nested intervals, endpoint rounding, negative/zero/small-positive gap and infeasible precision cases do not silently repair.
- Duplicate 6+6 succeeds and 7+7 rejects; IDs respect current/history/planned reservations and schema; failed plans consume none.
- Layer order preserves selected/nonselected subsequences and all item records; array bytes change only on real reorder.
- Delete all remains a valid static background scene but invalid sequence capture; history restores exact IDs/order.
- Undo plus redo stays at most 40, oldest eviction is bounded, no-op preserves redo, success-only branch clears it and later selection does not break Undo.
- Same-generation recycled ID cannot receive a captured old-revision action; genuine own provisional events remain valid.

## App, native interaction and visual review

- Exact accepted/draft/sequence/selection/lock/history snapshots verify every invalid/locked/stage-rejected operation.
- Fresh invalid text and precision companions survive canonical rollback, selection rejection and Hide; stale provisional DOM coordinates never replay.
- Ordinary invalid input preserves history immediately; same-value correction retains it, different valid correction clears only after successful stage.
- Provisional stage/paint failure and pointerup final-stage failure restore exact origin/stacks; post-final-publication failure retains one complete hidden transaction and truthful recovery status.
- Three or more consecutive owned pointermoves work; external selection/primary/lock/snap/viewport/lifecycle changes cancel and late release cannot commit.
- Native Select only can select the existing primary alone from multiple selection; neutral option is not an item, timeline state is membership and disabled inspector handlers cannot target primary.
- Geometry-independent commands, downloads, Unlock all and Hide remain usable when viewport/canvas is unavailable under ordinary policies.
- Trusted mouse, keyboard and touch-emulated workflows cover all operations, exact deltas, snap, locks, cancel, history and rapid-release first Undo/Unlock without fling suppression.
- Every lifecycle-table event is exercised, including same-ID successful replacement, failed/canceled/stale import/image, sequence-only import and successful Live-preserving replacement.
- Hidden edits stay hidden; fullscreen/manual/timed viewing cannot be edited in place; aids never rearm and marked-view suppression never resets incidentally.
- Actual raster and exported coordinates agree with the command; unchanged payloads and selection-only canonical/hash/raster equality are verified, not inferred from labels.
- Actual captures inspect unequal/rotated/outlined geometry, all authored ratios/letterboxes and legacy wide/tall views, not diagrams pretending to be rendered evidence.
- Desktop 1280×800, narrow 320×760, short 640×360 and 320×280 show all 12 complete longest labels, primary/lock/delta controls, 44-pixel targets and full focused row inside the true inspector aperture.
- Keyed row focus survives reorder/refresh; deleted-focus fallback is documented; no unnecessary second scroller or long text moves the captured canvas; Hide/Stop and corner/center targets remain reachable.
- Forced colors/reduced motion are inspected; physical touch/pen, actual zoom, cross-engine, OS file and assistive technology are separately PASS/FAIL/BLOCKED/NOT RUN.

## Resource, evidence and integration review

- At most 12 bounds per measurement pass, small sorting, one planned candidate/atomic final stage, bounded necessary validation passes and no removed validator.
- Memory ledger covers at most 40 exact before/after scene transactions, selection/ID metadata and bounded reservations; repeated select/undo/redo does not grow retained nodes or history.
- Same-runner baseline/candidate planning/handler-plus-layout and first-Hide median/p95/max are recorded; >50 ms arrangement work/delayed Hide is investigated, not hidden by timeout increases.
- Any proposed coverage-driven CI duration change has explicit independent review and measured-baseline rationale, preserves existing groups/assertions and is not counted as measured Feature 013 performance.
- Source is assembled; complete Node/native/package/documentation/whitespace/integrity gates actually execute; exact commands/versions/tree/runtime hash/bytes and actual inspected captures are recorded.
- Historical failures and unrun external acceptance remain visible. Source repairs rerun affected and final aggregate checks.
- Verified Feature 012 main, independent exact-tree review and required green exact-head CI precede Feature 013 integration. No collection, release, deployment or hosting follows implicitly.

Use PASS, FAIL, BLOCKED or NOT RUN only for executed procedures and their actual outcomes. A passing scanner is not accessibility conformance, browser emulation is not a physical device, and engineering evidence is not sensory or clinical clearance.
