# Clarifications and frozen bounded decisions

Feature 013 · 20 October 2026. These decisions promote the independently reviewed atomic multi-selection contract. They describe required behavior, not implementation or acceptance status. The [specification](spec.md) is the complete normative contract; [tasks](tasks.md) preserve every precise acceptance case. Live status belongs only to [the queue](../../project-queue.json).

## Selection, identity and equivalent controls

1. **Session state is closed and ordered.** Selection is exactly `{ids, primaryId}`. IDs are unique existing stable item IDs, normalized to current back-to-front draw order; primary is a selected ID or null only for empty selection. Reject hostile records, accessors, duplicate/missing IDs, unknown fields and nonmember primary. Reducers construct valid states rather than repairing hostile input. No group metadata exists.
2. **Primary means move anchor only.** Checking a new member makes it primary; removing primary chooses the frontmost survivor. Select all keeps a valid primary. Clear yields empty/null. Changing Move anchor preserves membership, cancels captured work, moves nothing and adds no history. Alignment and distribution do not depend on click order or primary.
3. **Select only is a real native route.** Empty/multiple selection displays a reserved empty-valued neutral option, never primary as the selected option. Every actual stable-ID option, including the previous primary, creates a singleton. The neutral option never mutates selection. Timeline and overlap actions select only; timeline pressed state reflects all membership until acted on.
4. **No implicit primary property editing.** Shape, size, position, color, effects, timing, Start after previous and Lock selected item require a true singleton. Disabled handlers reject if invoked directly. For multiple/empty selection, `readFields()` uses canonical item records plus allowed global edits, not stale disabled fields. Unlock all, Hide, downloads and allowed global controls remain usable.
5. **Native checklist is the selection display.** At most 12 labeled checkboxes include layer, shape, ID and lock state; count, primary, Move anchor and full labels remain reachable. Preserve 44 CSS-pixel targets, focus keyed by stable ID/control role, and the existing inspector scroll aperture. Delete focuses the documented nearest survivor or summary. No canvas outline, hidden modifier dependency, nested scroller without reviewed need, or pointer-capture layout shift is added.
6. **Pointer membership and movement are separate.** Plain down on an unselected hit selects it only; down on a selected hit keeps membership and makes it primary. Shift toggles membership only for that gesture. Keep topmost/hollow/tiny/touch/shadow/letterbox/non-primary rules, 4 CSS-pixel threshold, grab offset and capture. Locked hits are selectable and never click through. A canceled gesture retains its pointer-down-resolved selection; a subsequent explicit selection action cannot be overwritten by stale release.
7. **Identity needs three concepts.** Whole-scene replacement/accepted history advances scene generation. Independent selection, lock, preferences or authored content changes advance external interaction revision and invalidate captured work. An owner token identifies provisional gesture writes so they do not self-cancel; completed gestures advance external revision after ending ownership. Same-generation ID reuse after history clear/eviction is allowed only because callbacks check revision as well as generation and ID.

## Atomicity, raw text and history

8. **Cancel canonical state without erasing raw input.** Preserve exact user-authored text/value, invalid state and edit revision in a bounded per-field channel, including precision companions. Do not confuse provisional form repaint with authored edits. Rollback must not call the old field-refresh path that clears raw overrides or history. Build the next candidate from rolled-back canonical state plus actual pending edits, not all stale DOM values.
9. **Invalid ordinary input is not a canonical edit.** It conceals and remains visibly pending/correctable, but preserves canonical draft, selection and both arrangement stacks from the input event onward. Reject Undo/Redo and selection/primary transitions that would discard it. Same-value correction retains exact payload/history; valid different ordinary editing clears arrangement history only after successful validation/staging. Hide never erases fresh invalid text, and correction never reveals.
10. **Plan, then publish once.** Validate raw input, scene, selection, command, locks, identities and only necessary viewport geometry; compute one immutable complete candidate; validate output, locks and postconditions. Check identity again before one controller stage. Only a successful completed command publishes document, selection and history together. Rejection consumes neither history nor IDs. No-op follows required policy/lock checks and never stages or clears redo.
11. **Provisional and final failures differ.** Pointermove has no completed history publication. Preview-stage/render/UI failure or failed pointerup final stage rolls the whole gesture back to exact starting bytes and preserves both completed stacks. After successful completed-command/final-gesture publication, a later paint/UI failure conceals but retains that one complete hidden edit and matching history transition, with truthful failure text. Do not relabel it an atomic rejection or announce visible success.
12. **One 40-total transaction stream.** Generalize Undo/Redo arrangement for singleton and batch move/align/distribute/center/reorder/duplicate/delete. Entries contain exact before/after documents/selections, generation, kind and targeted IDs, not locks, pointer trails or bitmaps. Undo plus redo together is capped at 40. Selection-only/preferences/locks preserve it. Prepare history target before moving stacks; live selection equality is not required. Restore saved selection only after success. No-op preserves redo; successful branching clears it; actual incompatible document change invalidates the stream explicitly.

## Locks and coordinate precision

13. **All selected locks reject mutation, except duplicate.** Move, align, distribute, center, delete and targeted reorder reject if any selected item is locked, even an unchanged endpoint and before no-op optimization. Copies may originate from locked items but are unlocked; originals remain full-record-identical. Unselected locks guard records, not absolute order. History also rejects newly locked targeted reorder items and removal of a newly locked duplicate without consuming entries. No lock is restored or silently removed by arrangement history. Accepted history remains blocked by any lock.
14. **Accepted numbers are not eagerly quantized.** `Q(v) = Math.round(v * 100)` is a planning lattice, not permission to rewrite payloads. Multi-item commands write only genuinely changed item-axes. Orthogonal/unchanged axes, unselected records, selection-only changes, rejected/no-op commands, duplicate sources/copies, reorder survivors and cancellation keep exact accepted values. Pairwise translation invariance is integer-hundredth difference, not raw floating subtraction. Undo/Redo restores exact snapshots. Existing singleton helper output is an explicit compatibility exception, not a target for silent normalization changes.
15. **Zero is independently feasible.** For each multi-item axis, feasible deltas are exact-payload zero union the ordinary nonzero integer interval intersection using current inward envelope limits and endpoint corrections. The valid `2.80000000001` outlined-dot origin can round to an invalid 2.8; it must not move inward for zero/subquantum/outward request. In the opposite-bound fixture the ordinary intersection is empty and zero is the only valid result. A nonzero exact delta still requires the ordinary intersection; canonical insets never widen.
16. **Snap follows primary, not every item.** Active pointer/tap snap filters the complete feasible set for primary's 1/5/10 grid membership, retaining existing `Math.round` and ordinary half-step behavior. Zero qualifies only if primary's lattice center is on the grid; no feasible grid candidate rejects, never unsnaps or distorts spacing. Exact `(0,0)` and subthreshold no-gesture are unchanged after policy checks even when snap is on. Exact typed/nudge commands never snap. Multi-item out-of-bounds exact requests reject wholly; singleton edge-clamping stays unchanged.
17. **Actual shared geometry is command-specific.** Duplicate/delete/reorder/selection/snapshot history/exact normalized delta/singleton position-centering do not require viewport. Alignment/distribution/multi-centering and pointer mapping require positive finite actual viewport and finite derived content/scale/bounds/conversion. Reject underflow/overflow rather than guessing. Arrangement bounds use returned geometry kind, body plus outline/contour, not shadow; canonical validation envelope remains separately authoritative. Legacy arrangement uses current preview proportions; authored equal-ratio results are scale-equivalent.
18. **Comparison tolerance prevents drift, not validation.** One fixed normalized `EPS = 1e-9` never biases rounding, accumulates or widens inset rules. Alignment no-op uses requested-edge/midpoint spread ≤0.01+EPS only. A newly mutating alignment must also keep each edge/midpoint within 0.005+EPS of the original union target. Do not apply that latter requirement to the already-satisfied branch. Multi-center preserves satisfied axes within 0.005+EPS of 50 and otherwise uses one common rounded delta. Repeats preserve exact first-result bytes/history/redo.
19. **Distribution means equal edge gaps.** Require three items, sort by original leading edge with exact draw-order ties, preserve original outer span, and derive one nonnegative ideal gap. A validated existing result whose gaps are all ≥−EPS and spread ≤0.02+EPS is a comparison-only no-op before new targets. New output must meet nonoverlap, endpoint ≤0.005+EPS and gap-spread ≤0.02+EPS limits plus strict canonical validation. Reject rounding-induced overlap with the precision explanation; never push endpoints or enlarge span. Nested shapes mean originally sorted endpoint items need not stay put. Equal centers, entered gaps and key-object modes are excluded.

## Structure, lifecycle and boundaries

20. **Structural edits are atomic and bounded.** Duplicate preflights the 12-item cap, copies exact records in source draw order, appends one block, maps primary and selects copies. Allocate smallest free existing-schema IDs from current/history/planned reservations, at most 984; failed plans consume none. Delete selects the survivor at first removed index capped to the final array, or empty. Forward/backward swaps stable selected runs across one unselected neighbor without gathering or reversal. Reorder changes canonical array bytes, not stored item records.
21. **Lifecycle keeps existing authority.** Successful Apply/capture clears arrangement history only after success and retains valid selection/locks. Successful replacement/accepted history clears draft history, advances generation and selects first item or empty. Discard also clears history/advances generation, but preserves a prior singleton that exists in the accepted scene; otherwise it selects the first item or empty. Failed/canceled/stale replacement preserves stable state after any required rollback. Sequence-only import keeps editor history/selection; Load step is replacement. Do not turn all synchronous already-live replacement paths into new concealment. No replacement/history operation resets Feature 012 marked-view suppression or rearms aids.
22. **No new capability is hidden in this refactor.** Keep closed legacy/scene/sequence/journal validators, 12 objects, 40 total transactions, buffer limits, static startup, finite independent clocks and reachable Hide/Stop/End/Escape. No new fields, groups, overlay pixels, browser storage, network, timers/RAF loops, packages, security permissions, telemetry, collection, release or hosting. Unknown imported session/group/guide fields reject rather than disappear.

23. **CI coverage growth is a bounded reviewed proposal, not performance evidence.** The prepared native plan preserves all 178 existing groups and adds 22, for 200 prepared groups. The earlier group-count-only projection was superseded when independent review required actual batch geometry captures across all authored ratios and legacy wide/tall layouts, plus a frozen-baseline comparison. Recorded Feature 012 duration is 795.126 seconds. Conservative added-work estimates are up to 160 seconds for the initial new checks, 55 seconds for ratio visuals, and 100 seconds for six alternating baseline/candidate pairs, totaling approximately 1110.126 seconds. A proposed 1380-second (23-minute) native limit provides approximately 24% headroom; another 180 seconds gives a 1560-second (26-minute) limit for the same single job. Independent review is required before application. This is a coverage estimate, not measured Feature 013 performance. Current Feature 012 CI, required assertions, sandbox, read-only permissions, cleanup and packaging remain unchanged.

No open product decision blocks this bounded specification. Implementation details must satisfy the complete contract and be independently reviewed. Verified Feature 012 main, exact-source Feature 013 tests and CI remain separate gates; the accepted design review did not execute them.

24. **Shared-route timing uses an actual frozen baseline.** Load only the local, hash-pinned Feature 012 artifact in the same Chrome process/device as the candidate. Alternate ordering across six pairs of identical synthetic scenes and preserved singleton nudge/drag/first-Hide inputs. Retain every trusted raw sample and median/p95/max. Predeclare candidate-minus-baseline p95 ≤10 ms and each candidate event/Hide <50 ms as investigation gates. New batch drag and equal-gap operations have no baseline equivalent and are reported as candidate-only costs. The baseline is test-only, licensed and excluded from distributed runtime/package files; no network loading.

25. **Singleton half-hundredth compatibility is exact.** Active singleton placement/translation delegates the established helpers without a subtraction-based Q(delta)==0 preguard: target 25.005 from 25 must follow E.place to 25.01. Only explicit exact zero displacement, no actual gesture, and app cancellation/return-to-origin restoration avoid an active command. Multi-item zero/subquantum preservation remains unchanged. This clarification resolves a concrete arithmetic-boundary finding rather than broadening coordinate behavior.

26. **Preserved native ordinary-edit and hidden-layout contracts.** Successful ordinary input staging retains explicit dirty intent even if canonical bytes are unchanged; only a different successful canonical edit clears arrangement history. This does not turn arrangement no-ops into edits. Short-window inspector scroll rules apply to hidden and Live modes, preserving a complete focused control after resize concealment. The initial native failures and their repairs remain evidence, not waived assertions.

27. **Zero-final gesture preserves explicit dirty intent.** A drag that returns to its exact origin creates no transaction and restores the captured pre-gesture dirty intent, even when the underlying scene bytes equal accepted bytes. It must not re-enable export or change capture wording merely by recomputing dirty state from canonical equality.
