# Clarifications and frozen bounded decisions

20 October 2026. These decisions define feature 012 only. Implementation evidence is separate in the [single queue](../../project-queue.json). The parent task selected these conservative decisions under the approved roadmap; no security/hosting or broader feature authority is added.

1. **One optional editor surface.** The labeled native Show editor aids checkbox uses its checked state to reflect explicit arming, is initially unchecked, and becomes unchecked on disarming. Checking it arms a grid in valid visible static Live mode only. Grid defaults to 5 units; permitted values are 1, 5 and 10. Center guides default off. They are non-interactive editor marks, not shapes, a second preview, or exported metadata. Selection outlines are not in this increment.
2. **Snap is independent.** Current Off/1/5/10 snapping remains drag/placement-only. Grid setting/visibility does not change snap; thinning changes only which grid lines are painted. No imported or already-authored coordinates are quantized.
3. **Content-relative layout.** Obtain the validated `M.contentRect(scene, width, height)`. For axis length `L` and base step `s`, projected base spacing is `L * s / 100`, and stride is `max(1, ceil(8 / projectedSpacing))`. Paint positions `k * s * stride` strictly between 0 and 100, mapped into that content rectangle. Report the effective intervals `s * stride` separately for X and Y when thinned. At very small valid dimensions there may be no interior grid line; this is valid and is explained rather than replaced with an invented edge line. Reject nonfinite derived layout rather than looping or repairing it.
4. **Center lines and duplicate positions.** When enabled, paint horizontal and vertical center guides at normalized 50 even if the thinned grid does not include them. If a grid line occupies exactly the same axis/position, the renderer may deduplicate it and give the center style precedence. Tests allow no more than 200 total line records either way. No guide extends into a letterbox bar.
5. **Fixed non-animated styling.** Use a restrained neutral line style; no blinking, contrast inversion, responsive luminance changes, pulse or transition. The 8 CSS-pixel threshold is a legibility/product bound, not a physiological guarantee. Visual acceptance must inspect the actual narrow result.
6. **No layout wrapper.** The overlay is a canvas-aligned sibling with a content-clipped child. Application-created DOM/CSS only, `pointer-events: none`, `aria-hidden="true"`, no focusable descendants. At most 230 elements including containers; no third full-size canvas. Do not change canvas geometry or steal hit targets merely by enabling aids.
7. **Setting changes cancel old interactions.** Before aid/snap preference transitions that affect the overlay, cancel/roll back active drag or placement and invalidate stale work. Without an active gesture, changing aids cannot create a move/accepted-history entry, clear existing move history, change selection/locks, or dirty the scene. Rejected option values preserve the last valid preference and remove unsafe marks.
8. **Disarming is stronger than hiding.** Every concealment, lifecycle/fullscreen interruption, editor close, section change or departure from static Live removes and disarms aids. Successful scene replacement disarms before its replacement render without changing that route's existing reveal/conceal authority: synchronous New/Convert/preset paths that preserve an already active Live preview may still do so. Already-concealing imports remain concealed. Replacement never resets aid-affected provenance suppression. A fresh clean Show/Live action does not rearm them. Preferences remain session memory only; no storage. Always evaluate eligibility before touching overlay visibility, including after async completion.
9. **No marked-view provenance.** Main-canvas bytes remain unchanged, but the visible composite differs. End current provenance with existing `edit` before displaying aids, advance caller identity, invalidate a pending journal export preview, and latch aid-affected provenance suppression. Both the journal data getter and status getter must agree that association is unavailable; no prior clean record is substituted. Existing saved records are untouched.
10. **Only successful explicit clean starts reset suppression.** Resume Live/Show step/static Show or starting a new explicit finite item/sequence run may reset it after successful validated start with aids disarmed. A tracking-toggle, aid-off, render, delayed digest, correction, failed or repeat-lock-rejected Show, or Pause/Resume cannot. No new display action or timing capability is introduced.
11. **No schema expansion.** Do not change scene/sequence/journal versions or add end reasons. Existing `edit` records the interrupted clean interval internally; current marked-view journal association remains unavailable. Do not encode aid state in the scene hash or silently export a screen composite as a scene.
12. **Failure and visibility ordering.** Common cancellation clears/disarms aids synchronously before any later render. If overlay geometry/DOM work fails, clear it; if clearing or registration cannot be established, conceal the field. Aids cannot veto Hide/End/Stop/Escape, unlock, export or fullscreen Exit. No fallback timer repairs the overlay or restores its armed state.

## Boundary matrix

| Event | Aid result | Existing data/display behavior |
| --- | --- | --- |
| Valid static startup | Off; default preferences only | Existing one static Live startup; no timer. |
| Arm while valid eligible Live | Visible grid and optional centers | Scene bytes/history unchanged; provenance stopped/suppressed first. |
| Hidden preference change | Preferences only; disarmed | No reveal, timing or history. |
| Hide/End/Stop/Escape; invalid input; effective resize; hidden tab/pagehide | Clear and disarm | Existing rollback/concealment; no callback resurrection. |
| Editor closes or Scene/static Live mode is left | Clear and disarm | Preserve existing concealment/mode semantics. |
| Fullscreen request/change/failure or fullscreen Show | Always clear/disarmed | Existing explicit Show and accessible Exit remain. |
| Import begins, including eventual rejection/cancellation/stale completion | Clear/disarm at import start; never auto-return | Existing concealment and accepted/lock/history rules unchanged. |
| Successful synchronous scene replacement | Clear/disarm before replacement render; never reset provenance suppression | Preserve the route's existing field authority, including already-live New/Convert/preset paths; do not introduce global concealment. |
| Failed synchronous replacement | Never restore previously cleared aids or reset suppression | Preserve existing failure/invalid-input policy and prior data; no new reveal authority. |
| Ordinary valid Live shape/background edit with editor still eligible | May remain armed and recompute from valid draft | Current immediate static repaint and provenance suppression remain. |
| Apply/Discard/Undo/Redo/capture/export | Clear/disarm through existing concealment | Existing data/history/locks semantics unchanged. |
| Tracking digest completes | No overlay or reveal change | Suppression and current association unchanged. |
| Successful fresh clean explicit display start | Aids stay off | May reset provenance suppression for the new viewing action only. |

There is no open product decision blocking this bounded increment. Exact neutral color/line styling and measured performance budget are implementation choices to freeze and inspect before acceptance; neither may broaden behavior. Multi-selection/group/persistent-format choices are deliberately outside feature 012, not implementation TODOs here.

The pure model interface is `ImageryEditorAids.guideLayout(scene, {width, height}, options)`. Options may omit either known field or be omitted entirely, defaulting to `{gridStep: 5, centerGuides: false}`; unknown keys, accessors, invalid supplied types/values and unsupported records still fail closed. The result is `{contentRect, grid: {x, y}, center: {x, y}, effectiveInterval: {x, y}, count: {grid, center, total}}`; line arrays contain content-local CSS positions, effective intervals are normalized units, and counts bound all line positions.
