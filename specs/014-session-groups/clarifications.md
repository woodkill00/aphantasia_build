# Clarifications and frozen bounded decisions

Feature 014 · 20 October 2026. These decisions promote the reviewed conservative contract. They describe required behavior, not implementation or acceptance status. The [specification](spec.md) remains the complete normative contract and [tasks](tasks.md) preserve every precise acceptance case. Live status belongs only to [the queue](../../project-queue.json).

## Scope, identity and selection

1. **Flat session metadata only.** A group is exactly `{id, memberIds}`; there are 0–6 disjoint groups of 2–12 current scene items within the unchanged 12-item scene cap. No nesting, editable names, container node, layer container, parent transform, appearance/timing aggregate, persistence or file-format fields. Grouping is not a rendering primitive.
2. **Validate separately, then cross-check.** Canonical scene validation never receives groups. Validate closed ordinary group records/arrays, ordinary prototypes and data descriptors before reading values; reject accessors, sparse/side-property arrays, unknown keys, malformed/duplicate IDs, foreign members and overlap. Validate membership against the canonical scene. Canonicalization may reorder a defensive valid copy, never repair invalid membership or discard groups to permit another command.
3. **Metadata order is not layer order.** Group IDs are `group-1` through `group-999999`; member IDs retain `object-1` through `object-999999`. Group records and members sort by numeric suffix, so 2 precedes 10. Unit/member draw order derives from the current scene. A layer change preserves group bytes and does not gather members into a block. Derived “Group N” labels are not editable names.
4. **Selection must already be group-closed at pure boundaries.** `{ids, primaryId}` keeps unique current item IDs in draw order and a selected-item primary, or empty/null. The pure validator, planner and history reject a partial group. Only an explicit UI reducer action expands the chosen item's full group. This resolves the reviewed planner ambiguity: no silent planner/history expansion or malformed-input repair.
5. **Every selection route uses the same units.** Object selector, timeline and overlap cycle replace with the chosen member's complete unit and keep that actual member as primary. Checking adds the full unit and uses the checked member; unchecking removes the full unit, retaining primary when possible or using the frontmost remaining item. Plain down on an unselected hit replaces with its unit; down on a selected member preserves all selected units and uses that hit as primary. Shift toggle is selection-only. Select all retains a valid primary; Clear empties it; Move anchor changes primary only. Delete chooses the prior nearest surviving layer item, expands its unit and retains that actual nearest item as primary.
6. **No implicit isolation through controls.** Rename the native select to Select item or group, keeping stable item IDs as values. Empty/multi-item selection, including one group, shows the neutral placeholder rather than primary. Choosing the current primary from a mixed selection must produce a real native selection change. All member checkboxes are checked together, never indeterminate; timeline pressed state equals expanded membership. No keyboard focus, tampered event or old singleton helper may isolate a member.
7. **Two distinct counts.** State item count and arrangement-unit count, including groups versus ungrouped items, rather than an ambiguous selected count. Keep the existing at-most-12 checklist, bounded labels with ID/layer/shape/lock/group, grouping explanation and Move anchor. No second group tree/list or automatic selection outline.

## Grouping, properties and locks

8. **Group has exactly four outcomes.** Two or more selected ungrouped items form one new group. Exactly one existing selected group is a complete validated no-op with no ID allocation or redo loss. An existing group plus anything else rejects with an Ungroup-first explanation; it never merges or flattens. Fewer than two selected ungrouped items is ineligible, including directly dispatched events.
9. **Ungroup is one metadata transaction.** Dissolve every fully selected group at once. Preserve all item records/order, selected IDs, primary and unrelated/selected ungrouped items. No selected group is a no-op. No other command auto-ungroups. After Ungroup, former members remain multi-selected until an explicit singleton selection.
10. **Metadata is allowed under locks; record mutation is not.** Group/Ungroup and their metadata-only history are allowed with locks after full-record validation. Any selected lock rejects the whole move/align/distribute/center/delete/targeted-reorder command, including stationary endpoints and no-op optimizations. Duplicate may use locked sources but creates unlocked copies and preserves originals exactly. Grouping does not weaken the inherited lock guard.
11. **Ungroup before member editing or locking.** Individual shape/geometry/position/color/effect/timing, Start after previous and Lock selected item remain disabled and handler-enforced for grouped membership. `readFields()` cannot edit the implicit primary. To edit or lock/unlock a member, Ungroup and then explicitly select it. Unlock all remains available without ungrouping and adds no history. Global valid edits and unrelated ungrouped-item edits preserve valid groups; a new item is ungrouped and singleton-selected.
12. **No canvas dependency for metadata.** Group/Ungroup, selection, duplicate/delete/reorder and stored-snapshot history need canonical data, locks and identity, not arrangement geometry. Geometry-dependent commands retain positive finite viewport and finite derived bounds requirements. A canvas failure cannot block Hide, Unlock all, ordinary exports or otherwise valid data-only commands.

## Rigid arrangement units and precision

13. **A group is one rigid arrangement unit.** Units are complete selected groups plus selected ungrouped items, ordered by earliest member draw-order index. Their bounds union shared rendered body-plus-outline bounds, exclude shadows and include internal empty space. Exact leading-edge distribution ties use earliest member index, not group-ID order or primary. Shared returned geometry kind, including polygon-returning authored dot/circle, remains authoritative.
14. **Minimums count units, not members.** Align requires two units; equal gaps requires three. One group of three or twelve members cannot rearrange its own members. A sole group uses multi-item Center selection bounds, never the singleton X/Y=50 helper. One ungrouped singleton retains all inherited helper behavior, including Feature 013's half-hundredth compatibility clarification.
15. **One delta per unit-axis.** Align/distribute derive targets once from the original scene and apply one rounded integer-hundredth delta to every member of each affected unit-axis. Whole-selection movement/centering uses one common delta across all selected members. Never round/clamp each member independently. Any member lock/inset/postcondition failure rejects the whole command. No transforms, scaling, packing or geometry-union collision algorithm is added.
16. **Zero retains accepted raw values.** Keep the full feasible set: exact-payload zero plus valid nonzero intersection deltas. The outlined near-inset dot and opposite-bound dot may form a group whose only feasible axis delta is zero. Preserve unchanged/orthogonal axes and all accepted fractional residues on no-ops, rejected commands, copies, selection, metadata and history. Pairwise movement preserves integer-hundredth offsets, not raw floating subtraction. Pointer snap uses the actual chosen primary and existing grid qualification; only pointer placement may choose a nearest feasible delta.
17. **Inherited tolerances apply to unit boxes.** Fixed comparison-only `EPS = 1e-9` cannot bias rounding or relax canonical insets. Alignment spread ≤0.01+EPS is an exact-payload no-op; new outputs also stay within 0.005+EPS of the original target. Center satisfied axes within 0.005+EPS of 50 stay exact. Equal gaps use original outer span, nonnegative feasible box gaps and the inherited 0.02+EPS spread and 0.005+EPS endpoint checks. Internal empty space counts and infeasible precision rejects; no equal-center substitute. One hundred repeated commands preserve exact first-result bytes, group state and both stacks.
18. **Structural commands remain all-or-nothing.** Duplicate preflights total selected items and resulting groups, preserves source numeric payloads and appends copies in source draw order. Allocate new group IDs in source-unit earliest-member order, remap membership and primary, and leave selected ungrouped copies ungrouped. Delete removes whole selected groups/items and expands the nearest survivor fallback. Reorder uses the existing stable adjacent-crossing algorithm: grouped A/B in `[A,X,B,Y]` becomes `[X,A,Y,B]`, not a gathered block.

## Atomic publication, history and lifecycle

19. **Metadata-only requires raw-canonical equality.** Cancel/roll back a captured gesture without erasing fresh authored raw text. Validate the raw scene candidate; if it is valid but genuinely different from the stable draft, Group/Ungroup refuses both changes until that ordinary edit completes through its own gateway. It neither bundles nor pre-stages the edit. Invalid text conceals and remains pending; same-canonical correction preserves history. Hide is unconditional.
20. **Same scene is not a complete no-op test.** A plan exposes distinct document/group changes. After all validation and revision/current-lock checks, document-changing commands keep one final controller stage and one complete scene/groups/selection/history publication. Metadata-only Group/Ungroup publishes groups/selection/history without restaging identical scene data, repainting the canvas, altering dirty/hash/provenance identity, touching accepted history/sequence or creating/ending a visible interval merely because metadata changed. Complete no-op publishes/allocates nothing and preserves redo.
21. **Failure phases remain distinct.** Provisional-stage/paint/UI failures and final-stage rejection before completed publication restore exact starting scene/groups/resolved selection with prior completed stacks. After final document publication or metadata publication, a later paint/UI failure conceals but retains one complete matching transaction and truthful failure status. Never leave groups committed without history, call a hidden commit an atomic rejection, or overwrite failure with visible-success text. Metadata refresh is not permission to paint an identical scene.
22. **Static eligibility and identity still apply.** Metadata-only does not bypass fullscreen/manual-step/running-or-paused-playback gates. Hidden static editing remains allowed and hidden. Successful membership publication/history restoration advances external revision and invalidates captured group/selection work. Generation plus external revision is required because history clearing/eviction can release an ID in the same generation. Gesture-owned provisional writes retain their existing separate ownership treatment. No revision change grants reveal or aid-arming authority.
23. **One total history, including metadata.** The existing 40-total undo-plus-redo cap includes group and document commands. Snapshots hold exact before/after documents/groups/closed selections, generation, kind and immutable targeted item/group IDs, not locks or a second history. A real Group after Undo branches and clears redo despite equal scene JSON. A validated no-op preserves redo. Restore exact IDs from snapshots without allocation.
24. **History distinguishes rejection from incompatibility.** Before consumption, compare current document and groups to the expected endpoint plus generation; do not compare live selection. Validate target groups and saved closed selection. Ordinary raw/policy/lock/candidate failure preserves both stacks, current groups/selection and raw text. A genuinely incompatible document/group endpoint is the explicit stream-invalidation exception, with a bounded explanation, not an ordinary pop/apply rejection. Corrupt saved membership is not repaired. Current-lock document and targeted-reorder checks still apply, while metadata-only history is allowed with locked members.
25. **Pre-branch IDs are reserved.** Current groups, every retained before/after group snapshot in both stacks and already planned groups reserve at most `6 + 40*12 + 6 = 492` group IDs. Keep the inherited 984 item-reservation bound. Use bounded smallest-free scanning, not a lifetime ledger or million-entry registry. Reserve against redo before successful branching discards it. Failure consumes no ID; exhausted/hostile allocation cannot block Ungroup, otherwise allowed deletion, selection, Hide, Unlock all or export. Recycled text IDs cannot receive old-revision callbacks.
26. **Apply is not a replacement.** Successful Apply and Add/Replace capture retain valid session groups/selection but clear draft history only after success; serialized data remains flat. Ordinary successful different edits preserve groups and clear history. Successful Discard, accepted history and every whole-scene replacement clear groups/history and advance generation/revision even for identical canonical bytes or matching IDs. Preserve existing per-route locks and Live/hidden authority. Failed/canceled/stale replacement preserves stable metadata; sequence-only import retains it, while Load step replaces it. On successful Discard, if any session group exists anywhere in the draft, clear every group and select the first accepted item, or empty when none exists. With no groups, preserve an existing singleton selection if its ID remains valid in the accepted scene; otherwise choose the first accepted item or empty. Both branches clear draft history, advance generation/revision and retain the existing lock preflight and concealment.
27. **History concealment is independent of scene identity.** Direct metadata changes in a valid visible static draft may leave that exact scene visible. Group-only Undo/Redo still explicitly conceals/disarms under history policy without changing scene bytes/hash/dirty identity. That concealment may end a visible interval, but membership itself does not. Nothing resets the aid-affected provenance latch or rearms aids.
28. **The loss warning is part of acceptance.** State beside controls and in the guide: “Groups are only for this editing session. Apply and downloads do not save them. Loading, Discard, accepted-scene history or reload clears them.” Keep scene dirty semantics unchanged and give one bounded reset notice. No saved-groups badge, persistence, implicit reconstruction from matching IDs, unload workflow or schema version change.

Exports deliberately cannot prove retained grouping.
