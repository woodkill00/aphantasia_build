## A. Pure metadata, selection, unit planning and history

Extend the existing `imagery-app/src/selection-model.js` pipeline instead of looping mutating singleton handlers or introducing a second group controller. The candidate module currently exports `canonicalSelection`, `reduceSelection`, `arrangementBounds`, `plan`, `makeTransaction`, `recordHistory` and `planHistory`; its document field is named `document`. The specification's conceptual `planArrangement`/`scene` names describe responsibilities, not evidence that those exact exports already exist. Freeze the concrete caller/result mapping before parallel app/model edits, retaining closed fields and distinct `changedScene`/`changedGroups` semantics.

Required seams:

- `canonicalGroups(scene, groups)` validates ordinary closed metadata and current references, returning a defensive numeric-ID-ordered collection. No scene-validator/schema changes and no repair.
- `canonicalSelection(scene, selection, groups)` verifies exact draw order and full group closure. Pure planner/history callers must supply a valid closed selection; they cannot silently expand a partial group.
- `reduceSelection(scene, selection, groups, action)` implements only the specified UI unit expansion/removal and actual chosen/hit primary rules. Current state still validates; hostile input is not repaired.
- `selectionUnits(scene, selection, groups)` produces complete selected groups and ungrouped singletons, ordered by earliest member layer index, without requesting canvas geometry.
- `arrangementUnitBounds(scene, units, viewport)` unions the existing returned-kind body/outline bounds, excludes shadows and includes internal empty space. Preserve positive finite actual viewport and finite-derived-geometry guards only for commands requiring geometry.
- The pure planner adds closed Group/Ungroup variants, unit-aware coordinate variants and structural membership mappings. Return one immutable candidate with document, groups, closed selection, command kind, targeted item/group IDs, separate scene/group change flags and prepared mappings where needed. No controller, DOM, visibility, global allocator or publication side effect.
- History target preparation compares exact document/group endpoints and generation, validates target metadata/closed selection and current concrete locks, and prepares the entire restoration without consuming a stack. Ordinary rejection and explicit endpoint incompatibility remain distinguishable.

Implement metadata/selection validation first. Group accepts only at least two ungrouped selected items or an exact already-group no-op; mixed grouped-plus-anything rejects. Ungroup dissolves all selected groups in one operation while preserving selection. Unit minimums are two for align and three for equal gaps; a lone group centers as multi-item union. Keep one common rounded lattice delta per unit-axis and all inherited precision/idempotence branches, including zero-only feasibility. Do not reinterpret singleton helper outputs or independently clamp/normalize member coordinates.

Duplicate preflights item/group caps, then allocates both types of IDs and maps group memberships/primary before publication. Allocate copy groups in source-unit order, not source-ID order; append item copies in original draw order and leave ungrouped copies ungrouped. Delete removes complete selected group metadata and applies expanded nearest-layer fallback. Reorder preserves exact group bytes and stable adjacent-crossing item subsequences without gathering noncontiguous members.

Extend the single 40-total history entries with defensive before/after groups and immutable targeted group IDs. A changed group with equal scene bytes is a transaction; a complete no-op is not. Reserve current and both retained history endpoints before branching, including redo that success will discard. Group reservations are bounded by 492 and item reservations by the inherited 984. Smallest-free planning has no persistent allocator mutation; failures consume nothing; restoration uses original IDs.

## B. Atomic app publication, semantic controls and lifecycle

Keep one app gateway with two validated publication branches. Snapshot stable scene/groups/selection and validate fresh raw input after ownership-safe canonical rollback. Refuse metadata-only Group/Ungroup if a valid but different pending ordinary field candidate has not passed its own gateway. Do not auto-stage it or bundle it into grouping. Preserve fresh invalid raw text and prior completed stacks, including when interrupted during a provisional drag. Same-canonical correction retains history.

Enforce static-editor eligibility in handlers, not merely disabled controls. Metadata-only is still prohibited during fullscreen, manual step or running/paused playback. Hidden static editing remains available. Validate complete input/candidate, current locks, ID reservations and expected generation/external revision before publication.

- Document-changing operations retain the established single final controller stage and complete document/groups/selection/history publication. Final-stage rejection preserves stable state; post-final-publication paint/UI failure keeps one complete hidden transaction and truthful status.
- Metadata-only Group/Ungroup publishes groups/selection/history together, advances external revision and refreshes only bounded semantic UI. It must not call controller stage, canvas render/paint, provenance identity/interval logic or dirty recomputation merely because membership changed. Accepted history, sequence and aids remain unchanged.
- Complete no-op performs required checks but no stage/publication/allocation and preserves both stacks. A same-scene comparison alone cannot identify it.
- Provisional gesture failure or pre-finalization cancellation restores exact starting document/groups/resolved selection and existing stacks. An owned provisional write cannot self-cancel; external membership/selection/lock changes invalidate it. A late release cannot commit against recycled text IDs.
- Successful group-only Undo/Redo still conceals/disarms under existing history policy. Separate that explicit safety effect from scene identity or metadata publication. Current locks remain independent; no history snapshot restores/unlocks them.

Audit every selection entry point: native object select, checklist, all/clear, Move anchor, timeline, overlap, pointer hit/toggle, placement and deletion fallback. Rename the selector to Select item or group and keep the neutral placeholder for all empty/multi-item selections. Add Group selected items / Ungroup selected groups, item-versus-unit counts, bounded derived labels, whole-group explanation and session-loss warning. Keep the existing 12 native rows rather than a second nested group tree.

Enforce individual-property and Lock selected item guards in handlers/readFields. Users Ungroup, then explicitly select one item before editing/locking it. Keep Unlock all and allowed global edits; Add item remains ungrouped/singleton. Preserve keyed focus through grouping, membership refresh and layer reorder; activating Group/Ungroup retains button focus unless recovery is required. Keep full labels and 44 CSS-pixel targets through the existing aperture with no canvas reflow during capture.

Map every specification §8 lifecycle row to the actual accepted source route. On successful Discard, if any session group exists anywhere in the draft, clear every group and select the first accepted item, or empty when none exists. With no groups, preserve an existing singleton selection if its ID remains valid in the accepted scene; otherwise choose the first accepted item or empty. Both branches clear draft history, advance generation/revision and retain the existing lock preflight and concealment. Apply/capture retains groups but clears draft history on success. Ordinary successful different edits preserve groups. Discard, accepted history and explicit whole-scene replacement clear groups/history and advance generation/revision on success, including identical-byte/same-ID replacements. Respect current lock and route-specific Live/hidden behavior; do not impose blanket new concealment. Failed/canceled/stale completion retains stable state. Sequence-only import is distinct from Load step. No callback can reset aid-affected provenance or restore groups from an export.

Inspect all serialization/export/capture/history paths. Groups never enter canonical scene, sequence, journal, accepted history, provenance hash or downloaded hidden fields. Strict unknown group/selection import fields reject; imports do not strip or reconstruct them. Close/reload loses groups. Update user documentation only when actual implementation evidence supports its tense/status.
