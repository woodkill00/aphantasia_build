## Concrete risks and conservative resolutions

1. **Partial selections can escape through a forgotten route.** Expanding only checklist clicks leaves timeline, overlap, object selector, delete fallback or dispatched events capable of isolating a member. Pure/planner/history boundaries must reject partial membership, while the explicit UI reducer expands the complete chosen unit. Keep actual chosen/hit item primary, not the first member of a sorted group. Test all routes independently and include selected-hit preservation of other units.
2. **Stable metadata can accidentally depend on draw order.** Sorting group/member arrays by current layer changes bytes during reorder, making metadata history/provenance assertions misleading. Numeric suffix order is stable metadata order; unit presentation and distribution tie order derive separately from earliest current member index. Verify group-2 precedes group-10 and byte identity across the interleaved `[A,X,B,Y]` fixture.
3. **A group can be mistaken for a scene node or isolated primary.** A group is only metadata over existing items. It cannot supply transform, style, timing or stacking behavior. A sole group has multiple selected items, disables individual editing/locking and uses union-bound center, not exact singleton center. Handler and `readFields()` guards must survive tampered disabled controls. Ungroup preserves selection, so explicit singleton selection is still required afterward.
4. **Member count is the wrong arrangement minimum.** Three members in one group are one unit and cannot distribute internally. Two groups plus one ungrouped item are three units even if their sizes differ. Disable/explain based on unit count, report both item/unit counts and use unit bounds including empty space. Group boxes may overlap even when shapes do not; infeasible box gap rejects rather than packing or separating members.
5. **Per-member rounding destroys rigid offsets.** Unit targets are derived once; one rounded lattice delta per unit-axis must move every member. Preserve unchanged raw axes and inherited zero feasibility. The outlined near-inset dot plus opposite-bound dot remains valid at raw zero even when the ordinary interval is empty. Independent clamping/normalization would violate both rigidity and canonical validation. Include snap-primary grid qualification and the unchanged ungrouped singleton arithmetic boundary.
6. **Recomputing accepted geometry causes drift.** Apply inherited no-op predicates to unit bounds before calculating new targets. Keep alignment's 0.01+EPS spread predicate distinct from the new-result 0.005+EPS original-target test; preserve satisfied center axes and equal-gap endpoint payloads. Original-span widths 10/20/10 require leading edges 10/40/80, with one whole-group delta. Repeat each command 100 times and compare exact documents/groups/history/redo, not visual similarity.
7. **Same canonical bytes do not mean no transaction.** Existing app/history paths are scene-change based. Group/Ungroup can change membership while leaving canonical JSON identical, so early return on `sameScene()` loses legitimate history and redo branching. Use separate change flags and atomically publish group/selection/history. Conversely, a complete validated no-op must not allocate an ID, normalize data or clear redo.
8. **Reusing the current publisher restages identical scenes.** The candidate `publishArrangement` stages a document and updates scene dirty/provenance paths. Metadata-only publication needs a validated branch that avoids those calls and canvas repaint entirely. It still checks raw-candidate equality, static eligibility, locks, expected endpoint/generation/revision and prepared history. Bounded semantic refresh must not call a general renderer that paints the scene. Instrument these calls in tests rather than inferring them from equal pixels.
9. **Pending ordinary edits can be silently bundled into grouping.** A valid different raw candidate is not necessarily the stable canonical draft. Group/Ungroup must refuse both changes until the ordinary edit gateway completes; pre-staging before group validation is also wrong. A fresh invalid input during a grouped drag must survive rollback exactly. Restore canonical origin/groups/resolved selection and keep prior stacks without replaying stale provisional DOM coordinates. Hide conceals unconditionally and never erases correction state.
10. **Failure phases can leave half a transaction.** Provisional movement has no completed history, so preview-stage/paint/UI failure and failed final stage restore exact origin. Only successful final publication permits a subsequent paint/UI failure to retain one complete hidden edit. A metadata-publication UI failure likewise retains one complete metadata/history state and truthful status, without a partial rollback that leaves stale groups or consumed stacks. Test every phase separately.
11. **Metadata permission can accidentally bypass editing eligibility.** A no-stage branch still must reject fullscreen/manual-step/running-or-paused playback commands and directly dispatched events. It cannot switch mode or reveal to become eligible. Hidden static editing remains allowed. Grouping cannot rearm aids or reset their provenance suppression latch.
12. **History endpoint matching can be too weak or too strict.** Equal documents with different groups are incompatible; a later selection-only change is not. Compare document/groups/generation, not current selection, then validate saved closed target selection. Distinguish ordinary raw/policy/lock/candidate rejection, which preserves stacks, from genuine endpoint mismatch, which explicitly invalidates the unusable stream. Do not silently expand corrupt saved selection or discard foreign memberships.
13. **Locks need command-kind distinctions.** Metadata-only Undo/Ungroup changes no protected records and remains allowed. Document-changing history retains full-record and targeted-reorder checks. The native copy-lock test must use a reachable route: Ungroup copies, lock one selected singleton, Undo that metadata-only Ungroup, then duplicate Undo must reject with group/stacks intact. Unlock all permits that same history target. No group/history operation restores or releases locks.
14. **ID allocation can reuse the abandoned branch too early.** A Group after Undo must reserve both old stacks before clearing redo on success. Group IDs also survive in retained before/after snapshots. Clearing/evicting history may later release text IDs, so generation alone is insufficient; stale callbacks must also match external revision. Planning failure consumes no ID, and allocation failure must not block Ungroup/Hide/export or otherwise authorized deletion.
15. **Grouping can be confused with layer containers.** Noncontiguous group members remain noncontiguous under the exact stable adjacent-crossing algorithm; selected and nonselected subsequences do not reverse or gather. Group records stay byte-identical while real layer array bytes intentionally change. Copy groups are new identities, allocated in source-unit layer order, with items copied in source draw order and no offsets/timing edits.
16. **Byte equality is not lifecycle identity.** Apply retains groups; successful explicit replacement clears them even if item IDs and canonical bytes match. Discard and accepted history also clear, respecting current lock gates. Discard retains upstream singleton selection only when no groups exist; any group anywhere requires first-accepted-item fallback after all groups clear. Sequence-only import retains editor metadata while Load step replaces it. Reset only after success; rejected/canceled/stale image/import results cannot clear or restore groups. Audit every row of the lifecycle table rather than one generic reset helper.
17. **Session-only groups are intentionally unsaved.** Group metadata does not set scene dirty and is absent from downloads, captures and accepted history. A visible warning near controls and in the guide is therefore a requirement, not optional polish. Strict imports reject group fields rather than strip them. No geometry/ID matching reconstructs groups on reload; no saved-group badge or persistence is implied.
18. **Native numeric exports cannot verify session metadata.** Compare ordinary exported coordinates/order and separately inspect in-session group IDs/membership. The latter must not be smuggled into export to make tests convenient. Actual captures verify labels/raster/layout, not numeric no-drift. Keep test-only observation distinct from runtime public file formats.
19. **More labels can make required controls unreachable.** Group/count/lock/loss text can clip checklist rows or add a nested scroll surface. Preserve stable-ID/control-role focus and button focus on Group/Ungroup, the existing inspector aperture and 44 CSS-pixel targets. Inspect all 12 full longest labels at all four required sizes with focus and corner/center hits. Do not move the canvas during pointer capture or accept CSS arithmetic alone.
20. **Prerequisite or performance evidence can be overclaimed.** Pending Feature 013 native work is not accepted main, and accepted Feature 012 does not test groups. A bounded algorithm is not measured handler latency; count ratios or inherited CI budgets are not group performance results. Measure the exact assembled candidate and first Hide, retain failures, investigate >50 ms attributable work and obtain independent review/exact-head CI before integration.

## Bounded resource analysis, not measurement

- Current scene: at most 12 items. Current metadata: at most six groups and at most 12 total member references because groups are disjoint, not six independent 12-member allocations over different items.
- History: at most 40 total transactions across undo plus redo, with at most 80 retained before/after endpoints. Each endpoint has at most 12 ordinary items, six groups and 12 total member references, plus bounded selection and target IDs. Thus group snapshots have at most 480 group records and 960 member references before current/planned/copy overhead. This is a cardinality bound, not measured JavaScript heap bytes.
- Temporary reservation proof: at most `6 + 40*12 + 6 = 492` group identities and inherited `12 + 40*24 + 12 = 984` item identities. Bounded smallest-free scanning suffices; no million-slot registry, lifetime-ID list or persistent allocator is needed.
- Per-command work uses small deterministic sorts and bounded metadata/unit/member passes. Keep all canonical input/output/lock/controller validations and finite geometry checks. Do not promise a single validation pass or remove checks to meet a performance target.
- Metadata-only commands require no geometry, canvas allocation or scene repaint. No additional full-size buffer, renderer, network operation, storage API, timer or RAF is introduced. Repeated UI/history cycles must be measured for retained DOM/history growth.
- Same-runner synchronous metadata/arrangement handler-plus-layout and first-Hide median/p95/max must be recorded with instrumentation limits. No measured time, byte cost, successful browser result or timeout entitlement is established by these bounds.

## Constitution review

- **User control:** Hide/Stop/End/Escape and lifecycle cancellation remain unconditional; metadata, history and stale callbacks have no reveal/start authority.
- **Closed data and geometry:** group metadata is separately closed and cross-validated; canonical formats, strict insets, shared returned geometry and exact accepted payloads remain unchanged.
- **Local minimal scope:** bounded session metadata only; no persistence, identity account, network, telemetry, collection, packages or security expansion.
- **Scientific restraint:** caps, rounding tolerances and timings are engineering constraints, not sensory safety, efficacy, diagnosis or imagery measures.
- **Accessible equivalents:** native checklist/selector/buttons/anchor, full labels and focus recovery accompany pointer enhancement; actual layout and external accessibility evidence remain distinct.
- **Bounded cancellation:** 12 items, six groups, 40 total transactions, bounded reservations and revision-safe stale work; no new event trail, clock or buffer.
- **Exact-source evidence:** design review, local source identity and old run results cannot substitute for new code/native/visual/performance/package/integrity gates.
- **Single register/reviewed integration:** IF-050 remains the live task. Verified Feature 013 main, independent review and green required exact-head CI precede group integration. Release/hosting/collection remain separate.

No constitution exception is requested. Concrete interface names, keyed refresh and atomic publication organization must satisfy the fixed contract; they cannot silently change scope. Missing prerequisite identity, unresolved precision/atomicity/layout failures or unmeasured claimed performance block acceptance, not permission to weaken a test or broaden the feature.
